# Veya AI Assistance Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline with TDD and one fresh whole-change reviewer. Steps use checkboxes; one final user-prescribed phase commit.

**Goal:** Optional reviewed intent parsing and grounded meetup assistance, functional with mock and failed OpenAI.
**Architecture:** Shared structured schemas, bounded server-only provider/task service, explicit cookie/origin APIs and focused optional UI components. Engine and stored proposals stay deterministic.
**Tech Stack:** Existing TypeScript/Zod/Next/React/pg/Vitest/Playwright plus built-in fetch. No added dependency.
**Spec:** docs/superpowers/specs/2026-09-30-ai-design.md

## Global Constraints
- Phase 5 only; no mandatory AI, live provider tests, deployment or Phase 6 work.
- Input idea1..500; activities<=10/80chars; location<=120; date/budget hints<=80; strict ordered real ISO dates.
- OpenAI fixed chat/completions, model gpt-4.1-mini default, 1000 tokens, store=false, redirects rejected, 64KiB envelope, 8000ms deadline, no retries.
- Public context only; no personal group data, keys/logging, AI DB mutation or transaction held over network.
- Existing revision/auth/closed-state checks remain authoritative. Exactly one phase commit and fast-forward push.

## Review Focus
- Ignored abort or stalled response stream still returns local fallback within deadline.
- Valid JSON with invented reason codes/extra fields cannot describe unsupported attendance or budgets.
- Empty public activity list never promotes private preferences into prompts or output labels.
- Membership/session/revision changes during generation reject stale/unauthorized results without losing votes.
- Slow parsing or failure never overwrites manual fields or blocks ordinary invite creation.
