# Veya Backend Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. Follow the test-first steps and record results in CODEX_PROGRESS.md.

**Goal:** Complete the persistent, guest-authorized Phase 2 backend.

**Architecture:** PostgreSQL migrations and transactional service functions behind thin Next route handlers; server-only secrets and safe public projections.

**Tech Stack:** Existing Next/TypeScript/pg/Zod; native embedded PostgreSQL for dev/tests; tsx CLI.

**Spec:** `docs/superpowers/specs/2026-09-30-backend-design.md`

## Global Constraints

- Phase 2 only. Landing remains the Phase 1 local preview.
- 256-bit guest tokens, hashes at rest, 30-day session expiry, 144-bit public slugs.
- No internal identities, session secrets or other participants' private details in HTTP responses.
- Native PostgreSQL integration tests; no mocked database.
- One final commit: `phase-2: backend and data model`; no push/deployment.

## Review Focus

- Expired/revoked/forged guest credentials cannot mutate stored data.
- Concurrent or duplicate submissions create one membership and atomic child data.
- Another guest cannot edit/close the creator's intent or modify another membership.
- Failed migrations and data updates roll back completely.
- Public reads and generic failures do not leak secrets, identifiers or private notes.
