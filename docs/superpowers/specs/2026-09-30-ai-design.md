# Veya Phase 5: optional structured AI assistance

## Scope and execution
Complete exactly Phase 5 of the autonomous roadmap, preserving Phases 1–4.
Implement inline on the supplied work branch, one final `phase-5: AI integration`
commit and authorized fast-forward publication to main. No deployment or Phase 6.
The user's autonomous instruction overrides skill approval pauses and intermediate
commits. One fresh independent whole-change review follows implementation.

Three approaches considered: mandatory AI during create/results (adds latency and
failure to the core flow); background generated snapshots (needs cache, jobs and
more lifecycle complexity); explicit optional server tasks (chosen, no extra
infrastructure, usable immediately with deterministic local fallback).

## Tasks and contracts
`ParsedIntent`: type general/meet/travel/game/study, activities (<=10, <=80 chars),
location nullable <=120 chars, dateHint nullable {startDate,endDate,text<=80},
budgetHint nullable literal text <=80. Real ISO dates ordered; hints are advisory,
not participant constraints or monetary limits. Parse input {text:1..500 chars,
referenceDate:local ISO date,timeZone:valid IANA zone}. Relative dates resolve
against the supplied reference date, never an implicit model/server clock.

`PlanContext`: only public intent {rawText,activities,location} and proposal
{startAt,endAt,availableCount,partialCount,totalCount,durationMinutes,shortened,
activity,budgetAssessment}. Explicit projection; no full ResultsView, names, raw
availability, notes, preferences, individual budgets, vote identities or DB IDs.

`suggestPlan(context)` returns {title:1..100,idea:1..240}, creative text shown as
an optional meetup idea, separate from deterministic scheduling facts. It cannot
replace proposal title/window/attendance/explanation, change votes or persist data.
`explainPlan(context)` asks for a structured list of applicable reason codes
(everyone/largest_group/partial/shorter/budget_overlap/budget_compromise/
different_currencies/activity). Validate against actual context, then render
trusted factual phrases. No unsupported AI attendance/cost/time assertions.

Provider `complete({task,input},signal):Promise<unknown>` produces structured JSON.
Task service validates input before provider work, validates output plus semantic
reasons, and returns {data,source:mock/openai/fallback}. Pure deterministic mock
parses a documented small English/Russian vocabulary, literal location/budget and
relative/explicit dates; unknowns stay empty for user review. Mock is not an LLM.
Relative phrases match complete Unicode words, including day after tomorrow /
послезавтра. This week means today through Sunday of the Monday–Sunday calendar
week. Arithmetic outside four-digit real ISO dates leaves the date hint unknown.

## OpenAI and failure behavior
AI_PROVIDER=mock is the local default. AI_PROVIDER=openai uses server-only
OPENAI_API_KEY and optional OPENAI_MODEL (default gpt-4.1-mini). Missing key selects
local fallback without breaking configuration, landing, creation or results.
Built-in fetch posts to fixed https://api.openai.com/v1/chat/completions with
strict JSON Schema, max_completion_tokens=1000, store=false, redirect=error,
AbortSignal, safe response validation and <=64 KiB envelope. No dependency needed.
One attempt, no retries, overall task deadline 8000ms including body read;
Promise race bounds providers that ignore cancellation. Reject refusal/truncation,
invalid JSON/schema/reasons, 429/5xx/network errors and fall back to mock. Never log
or return keys, prompts, provider error bodies or internal details. Invalid user
input is 400, not fallback. All tests inject transport; no live API/key required.

## Integration and data boundaries
POST /api/ai/intent is same-origin, no-store, application/json <=16KiB; no DB or
session required. Optional Help with details button previews parsing. Apply details
is explicit and updates editable type/activity/place and advisory hints, preserving
creator name/reply lifetime. Dismiss/failure/manual create remain usable. No auto
requests; mention that suggestions may use AI before the user clicks.
StructuredIntent adds optional dateHint/budgetHint to existing JSON, with shared
Zod validation; old records remain valid, no SQL migration. Applied hints are
public creator-reviewed intent data; they do not alter scheduling/expiry/budgets.

POST /api/intents/[slug]/assist takes only {suggestionKey,revision}. Existing
active session and creator/member access required; same origin/body bounds. Resolve
current proposal under existing result transaction, project minimal public context,
release DB locks before parallel idea/explanation tasks. Revalidate authorization
and key/revision after completion; stale =>409. No AI network call inside a DB
transaction and no proposal regeneration caused by AI outputs.
Optional Get a meetup idea on each result card shows idea and grounded explanation.
Controls never gate voting/confirmation. New keys/revisions reset transient hints;
ordinary votes preserve them. React renders plain text, no AI HTML/links.
